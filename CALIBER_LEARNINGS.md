# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[correction]** Production API is `https://api.ballup.net` — use `--dart-define=USE_LEGACY_SUPABASE=false --dart-define=API_BASE_URL=https://api.ballup.net` for real-device or hosted-backend runs; do not default to legacy Supabase or `localhost` unless explicitly doing local backend dev.
- **[gotcha]** Root `docker-compose.yml` only `expose`s port 8000 on the Docker network — `curl http://localhost:8000` and the Android emulator (`10.0.2.2:8000`) need a gitignored `docker-compose.override.yml` with `ports: ["8000:8000"]`.
- **[env]** `docker compose` does not auto-load `backend/.env` — from repo root run `docker compose --env-file backend/.env up -d --build`; without it `POSTGRES_*` and `JWT_SECRET` default to blank strings and `db` stays unhealthy.
- **[fix]** If compose fails with `container ... db ... is unhealthy` plus warnings that `POSTGRES_*`/`JWT_SECRET` are unset, tear down and restart with `--env-file backend/.env` (recreate containers if the first attempt ran with blank env).
- **[gotcha]** `flutter run` from the monorepo root fails with "No pubspec.yaml" — the Flutter project root is `baller_app/`.
- **[gotcha]** `USE_LEGACY_SUPABASE` defaults to `true` in `AppConfig`; a bare `flutter run` expects Supabase dart-defines and throws at startup — always pass `--dart-define=USE_LEGACY_SUPABASE=false` plus `API_BASE_URL` for API mode.
- **[pattern]** Prefer repo-root `.vscode/launch.json` launch configs (`cwd: baller_app`, pre-set `toolArgs`) over ad-hoc `flutter run` commands when choosing dart-defines.
- **[gotcha]** API mode is not fully migrated — several UI files still call `Supabase.instance` directly (`home_page.dart`, `avatar.dart`, `profile_creation_page.dart`, `create_map_window.dart`); new data/auth work must go through repositories, and API-mode screens may break until those call sites are updated.

- **[correction]** When the user targets hosted `api.ballup.net` with B2 configured in the production container, implement full upload migration (`UploadRepository` + `/uploads/presign`) — do not defer avatar/court uploads assuming local Docker lacks B2.
- **[gotcha]** `POST /auth/register` seeds a profile row with an empty `username`; `ProfileRepository.hasProfile()` must require a non-empty username — a bare `GET /profiles/me` 200 is not enough or onboarding is skipped.
- **[pattern]** API-mode image uploads are two steps: authenticated `POST /uploads/presign` via `ApiClient`, then unauthenticated `PUT` bytes to the returned `upload_url` via a separate bare `Dio` (not `ApiClient` — its interceptor adds Bearer auth and the API base URL).
- **[convention]** `/uploads/presign` body: `kind` is `avatar` or `court_image`; `court_id` is required for `court_image`; persist the returned `public_url` (e.g. as `avatar_url` via `ProfileRepository`).
- **[env]** `/uploads/presign` returns 503 when `B2_KEY_ID`, `B2_APP_KEY`, and `B2_BUCKET` are unset in `backend/.env` — production `api.ballup.net` may have B2 while local compose often does not.
- **[gotcha]** Importing both `package:dio/dio.dart` and `package:supabase_flutter/supabase_flutter.dart` causes ambiguous `Headers` — use `import 'package:supabase_flutter/supabase_flutter.dart' hide Headers;` when referencing Dio's `Headers.contentLengthHeader`.
- **[fix]** Switching `API_BASE_URL` (e.g. `10.0.2.2:8000` → `api.ballup.net`) leaves JWTs from the old backend in `TokenStorage`; on 401/403 from `/profiles/me`, `AuthGate` should sign out and return to login — otherwise the app hangs on an infinite loading spinner.
- **[gotcha]** `docs/deploy/local.md` shows bare `docker compose up` and suggests a repo-root `.env`, but env vars live in `backend/.env` — follow CLAUDE.md (`docker compose --env-file backend/.env`) instead of the doc's quick-start.

- **[convention]** Password reset is Supabase-only today (`AuthService.resetPasswordForEmail`, ResetPassword pages) — no backend endpoint exists; API mode throws `UnsupportedError` until a FastAPI reset flow is added.
- **[pattern]** Before starting local Docker for emulator dev, confirm the user's target backend — if they say they use `api.ballup.net`, skip local compose and run Flutter with `API_BASE_URL=https://api.ballup.net` (verify with `GET /health` first).
